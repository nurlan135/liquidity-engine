# Codebase Concerns

**Analysis Date:** 2026-09-04

## Tech Debt

**Zero domain implementation — scaffold only:**
- Issue: The repository is a stock `create-next-app` scaffold plus shadcn `components/ui/*`. None of the Liquidity Engine domain described in `reference/design.html` and `reference/institutional_rules.md` (liquidity map, dealing range, SMT divergence, execution protocol, order ticket, sentiment averaging) is implemented anywhere.
- Files: `app/page.tsx`, `app/layout.tsx`, `app/globals.css`, `components/ui/*`, `lib/utils.ts`
- Impact: Every future phase starts from zero; reference specs are non-executable HTML/markdown with hardcoded values, not components or types.
- Fix approach: Treat `reference/design.html` as a visual spec only. Build the domain layer first (`lib/liquidity/*`, `lib/smt/*`, `lib/sentiment/*`) before wiring UI, and delete or replace the boilerplate `app/page.tsx` hero.

**Stub utility module:**
- Issue: `lib/utils.ts` is a single line — `export { cn } from "cn"` — re-exporting the third-party `cn` npm package instead of the standard shadcn `clsx` + `tailwind-merge` implementation. Every shadcn component in `components/ui/*` expects a local `cn` helper; this indirection adds a needless dependency and hides the class-merge logic.
- Files: `lib/utils.ts`, `components/ui/button.tsx`, `components/ui/card.tsx`, `components/ui/dialog.tsx`, `components/ui/calendar.tsx`, `components/ui/toast.tsx`, `components/ui/dropdown-menu.tsx`
- Impact: If the `cn` package changes behavior or is removed, all UI components break. Tailwind class conflicts (e.g. `px-2` vs `px-4`) may not resolve correctly depending on what `cn` actually exports.
- Fix approach: Replace `lib/utils.ts` with the canonical implementation (`clsx` + `tailwind-merge`, add both deps) and remove the `cn` dependency from `package.json`.

**Declared dependencies with zero usage:**
- Issue: `zustand`, `lightweight-charts`, `date-fns`, `date-fns-tz`, `react-day-picker`, `@base-ui/react`, `lucide-react`, `class-variance-authority`, `tw-animate-css` are all in `package.json` but imported nowhere in `app/`, `components/`, or `lib/` (verified by grep — zero hits outside `package-lock.json`).
- Files: `package.json`
- Impact: Bloated `node_modules` / install time, wider supply-chain surface, and false signal about what the stack actually uses.
- Fix approach: Keep only what the first real phase needs; remove the rest and re-add when actually imported. At minimum decide charting (`lightweight-charts`) vs. alternative before building the chart panel.

**Boilerplate metadata and branding:**
- Issue: `app/layout.tsx` metadata is still "Create Next App / Generated by create next app", `app/page.tsx` links to Vercel templates, and `app/favicon.ico` / `public/*.svg` are stock Next.js assets.
- Files: `app/layout.tsx`, `app/page.tsx`, `app/favicon.ico`, `public/next.svg`, `public/vercel.svg`, `public/file.svg`, `public/globe.svg`, `public/window.svg`
- Impact: Ships placeholder branding and dead outbound links if deployed as-is.
- Fix approach: Replace metadata, landing content, and icons during the first UI phase.

**Empty config files:**
- Issue: `next.config.ts` is an empty `NextConfig` placeholder (no images, headers, strict mode flags, or bundle options). `postcss.config.mjs` is stock. No `instrumentation.ts`, no `middleware.ts`, no route handlers.
- Files: `next.config.ts`, `postcss.config.mjs`
- Impact: No security headers, no image optimization policy, no API layer for future market-data/sentiment fetching — these decisions will hit all at once when backend work starts.
- Fix approach: Add headers and config incrementally as routes/APIs are introduced; don't leave the empty config unreviewed past the first backend phase.

## Known Bugs

- Symptoms: Working tree is on branch `master`, but the default/remote convention is `main`. New branches and PRs may target the wrong base.
- Files: Git config / remote (no code file)
- Trigger: Running `/gsd-*` commands that branch from or open PRs against `main`, or pushing `master` to a remote whose default is `main`.
- Workaround: Confirm default branch with `git remote show origin` and rename (`git branch -m master main`) before starting phased work.

**Untracked scaffold additions not yet committed:**
- Symptoms: `components.json`, `components/`, `lib/`, `reference/` are untracked (`??` in `git status`); `app/globals.css`, `package.json`, `package-lock.json` are modified and uncommitted.

## Security Considerations

**No authentication, validation, or secrets handling exists yet:**
- Risk: The planned app ingests broker sentiment data, session/kill-zone timing, and eventually live market data. There is currently no auth layer, no input validation library (no `zod` in `package.json`), no rate limiting, and no server-side code to put them in — but the reference design implies trusted numeric inputs (entries, SL/TP, confidence scores) that will eventually come from user input or scraped feeds.
- Files: `app/page.tsx`, `app/layout.tsx`, `next.config.ts` (no headers), entire repo (no `middleware.ts`, no API routes)
- Current mitigation: None — there is nothing to attack yet (static scaffold, no env files present, `.gitignore` correctly excludes `.env*`).
- Recommendations: When API routes arrive, add `zod` validation for all numeric inputs, set `Content-Security-Policy` / `X-Frame-Options` headers in `next.config.ts`, and keep any broker/API keys server-side only (never `NEXT_PUBLIC_`).

**`.env*` ignored but no `.env.example`:**
- Risk: Future market-data / sentiment integrations will need keys; without an `.env.example` template, contributors guess variable names or hardcode values.
- Files: `.gitignore` (correctly ignores `.env*`), repo root (no `.env.example`)
- Current mitigation: `.gitignore` coverage is correct.
- Recommendations: Add `.env.example` with placeholder names (no values) at the same time the first external data source is integrated.

## Performance Bottlenecks

**No data layer, so no measured bottlenecks — but two predictable ones:**
- Problem: The reference design's center panel promises a `lightweight-charts` canvas with FVG boxes, order blocks, and dealing-range overlays refreshed on 15M/5M/1M data, plus cross-market SMT comparison (e.g. NQ vs ES, EURUSD vs DXY).
- Files: `reference/design.html` (spec), future chart component (does not exist yet)
- Cause: Rendering many overlay primitives per candle update and polling two symbols at low timeframes will churn React renders if overlays are stored in component state or a naive zustand store.
- Improvement path: Keep candle/overlay data outside React state (chart series APIs + refs), throttle updates to closed candles, and use a single zustand store with selectors per panel — decide this before building the chart, not after.

## Fragile Areas

**shadcn + Tailwind v4 + `shadcn/tailwind.css` import chain:**
- Files: `app/globals.css`, `components.json`, `components/ui/*`, `postcss.config.mjs`
- Why fragile: `app/globals.css` imports `tailwindcss`, `tw-animate-css`, and `shadcn/tailwind.css` in a specific order with `@custom-variant dark` and `@theme inline` tokens. Upgrading `tailwindcss`, `shadcn`, or `@base-ui/react` independently can break the token chain (`--color-*`, `--radius-*`) or the dark variant, silently degrading every UI component.
- Safe modification: Change one styling dep at a time, then run `next build` and visually check `components/ui/calendar.tsx` + `components/ui/dialog.tsx` (the most token-dependent components).
- Test coverage: None — no tests exist.

**`LayoutProps<"/">` in root layout:**
- Files: `app/layout.tsx:20`
- Why fragile: Uses the Next.js 16 typed-routes `LayoutProps` helper. If typed routes are disabled or the Next version changes, this type import breaks the build of every page.
- Safe modification: If touching the layout, verify `next build` passes; fall back to `{ children: React.ReactNode }` if the helper disappears.
- Test coverage: None.

**TypeScript `target: ES2017`:**
- Files: `tsconfig.json`
- Why fragile: Default scaffold target predates modern APIs (`Array.prototype.at`, `Object.hasOwn`, `Intl` timezone features relevant to Kill-Zone/session logic with `date-fns-tz`). Code using them compiles but fails on older browsers, or forces downlevel helpers.
- Safe modification: Raise `target` to `ES2020`+ (and matching `lib`) when writing session/time logic; verify with `next build`.
- Test coverage: None.

## Scaling Limits

**Static-only deployment assumed:**
- Current capacity: A single static Next.js page serves fine anywhere.
- Limit: The first polling loop for live prices/sentiment, or any per-user state, has no backend, cache, or database — client-side fetching from broker endpoints will hit CORS and rate limits immediately.
- Scaling path: Introduce Route Handlers (`app/api/*`) as a proxy/cache layer with short-TTL caching before adding any live data panel.

## Dependencies at Risk

**`cn` npm package (opaque micro-dependency):**
- Risk: Non-standard package providing the critical `cn` helper; unknown maintenance status and behavior vs. the canonical `clsx` + `tailwind-merge` combo every shadcn doc assumes.
- Impact: All six `components/ui/*` files depend on it transitively via `lib/utils.ts`.
- Migration plan: `npm i clsx tailwind-merge && npm uninstall cn`, rewrite `lib/utils.ts` to the canonical two-liner.

**Next.js 16.3.4 + React 19.2.8 (bleeding edge):**
- Risk: Major-version-new Next with breaking changes (this repo's own `AGENTS.md` warns APIs "may all differ from your training data" and mandates reading `node_modules/next/dist/docs/` before writing code). AI-generated code from training data is likely wrong for this version.
- Impact: Plans or patches written from memory (layouts, metadata, caching, fonts) may fail to build.
- Migration plan: No downgrade needed, but every phase involving Next.js APIs must follow `AGENTS.md` and read the vendored docs first; pin exact versions until the app stabilizes.

**`shadcn` CLI package as a runtime dependency:**
- Risk: `shadcn` (the component-registry CLI) is listed under `dependencies` rather than `devDependencies` in `package.json`.
- Impact: Ships unnecessary code to production installs; minor bloat, not a breakage risk.
- Migration plan: Move `shadcn` to `devDependencies` on the next `package.json` edit.
