## Common Pitfalls

### Pitfall 1: W1 fix ripples into every `selectLastClose` consumer (position/bias/DOL/levels)
**What goes wrong:** `selectPosition`, `selectBias`, `selectDOL`, `selectLevels` all read `selectLastClose()` [VERIFIED: src/lib/store.ts:148-185]. Changing its basis shifts all four outputs intraday — existing unit/render expectations pinned on forming-close values break.
**Why it happens:** Fixing the selector without updating the pinned expectations.
**How to avoid:** Change the one function, then run the full suite and re-pin only expectations that encode the old skew; add one dedicated forming-vs-closed divergence case (forming candle with far close → position/bias computed off prior closed close). Direction is locked by Phase 1 D-04 (closed-only math) [VERIFIED: .planning/phases/01-data-foundation-ict-core/01-CONTEXT.md:16].
**Warning signs:** `store.test.ts` position/bias/DOL cases fail after the one-line fix; fixture uses a `forming: true` last row [VERIFIED: src/lib/store.test.ts:18-26].

### Pitfall 2: Price-line proliferation breaks autoscale / readability
**What goes wrong:** 1 EQ + 1 DOL + 2 quadrant + up to 4 OTE-boundary lines = 8 horizontal lines; lightweight-charts autoscales to include all price-line prices and the axis fills with overlapping titles.
**Why it happens:** Rendering every `LevelsOutput` field as its own line (both OTE pockets × both bounds).
**How to avoid:** D-03 says thin dashed lines in EQ style, but count is planner discretion — recommend 4 lines max (Q1, Q3 + one line per OTE pocket mid or pocket bounds only for the bias-relevant side), `axisLabelVisible` default, short titles. Keep DOL solid vs OTE dashed visually distinct. Exact set is [ASSUMED — needs planner + UI-gate sign-off].
**Warning signs:** Chart looks striped in dev; axis labels collide; `removePriceLine` refs leak (old lines never removed on update).

### Pitfall 3: D-04 `stale:true` latches forever if success path doesn't clear it
**What goes wrong:** Refresh-catch sets `stale:true`, but a later successful refresh must restore envelope truth — success already writes `stale: json.stale` [VERIFIED: src/lib/store.ts:112-121], so clearing is automatic *if* the catch doesn't also need `lastUpdatedISO` nulling (it must not — last-known age is what the strip shows).
**Why it happens:** Over-eager catch that nulls `lastUpdatedISO` or forgets the success path already resets `stale`.
**How to avoid:** Catch sets `{ lastError, stale: true, inFlight: false }` only; candles/contractHint/lastUpdatedISO untouched (preserve-last-known precedent already in the catch comment [VERIFIED: src/lib/store.ts:122-128]). Success path unchanged.
**Warning signs:** Strip stuck on STALE after recovery; `chartStatus` never returns to live.

### Pitfall 4: Header copy hydration / clock drift
**What goes wrong:** Header freshness needs a ticking `now` (StatusStrip 10s-tick precedent) but the poll loop stays the single store writer — a header-local `useState(now)` + `setInterval` is correct; deriving from store writes or `Date.now()` inline per render is not testable and flickers.
**Why it happens:** Copying the poll cadence (60s) instead of the display tick (10s), or computing age outside `deriveStatus`.
**How to avoid:** Reuse `deriveStatus({ stale, lastUpdatedISO }, now)` + `formatStripAge` exactly like StatusStrip [VERIFIED: components/dashboard/status-strip.tsx:31-40]; terminal-shell already owns a 10s `now` tick [VERIFIED: components/dashboard/terminal-shell.tsx:44-48] — reuse it. Azerbaijani copy only.
**Warning signs:** Header disagrees with strip; SSR/client age mismatch on first paint.

### Pitfall 5: D-07 steps that only pass on lucky dates
**What goes wrong:** DST-date step asserting a *transition* happens today fails 364 days a year; rollover-banner step asserting the banner is *visible* today fails outside rollover weeks (September has neither [ASSUMED]).
**Why it happens:** Confusing live-presence assertions with path/rendering assertions (Phase 3 D-10 settled this: rendering spot-checks, not event-triggered proofs [VERIFIED: .planning/phases/03-production-deploy-verification/03-CONTEXT.md:29]).
**How to avoid:** DST-DATE asserts candle `date` strings are valid `YYYY-MM-DD` Baku business days + page renders (fail-closed parse, like ENVELOPE); ROLLOVER-BANNER asserts the *path* exists (page contains the banner slot-hook code or shows it when the flag fires — e.g. grep build output / fetch page and assert slot contract, plus document the manual rollover-week check). STALE/502 step asserts `no-store` + `Retry-After: 60` contract on the 502 shape [VERIFIED: app/api/yahoo/route.ts:14-20] against a preview/kill-switch target the planner defines — never against prod.
**Warning signs:** Script green today, red tomorrow with no code change.

### Pitfall 6: `checkReanchor` removal breaks the rule-table test import
**What goes wrong:** `range.test.ts` imports `checkReanchor` directly [VERIFIED: grep src/lib/ict/range.test.ts]. Deleting the export without rewriting the tests reds the suite.
**Why it happens:** Treating D-08 as a one-line deletion.
**How to avoid:** Delete + rewrite the rule-table cases against the rolling-recompute behavior they actually pin (close-break retires / wick ignored / equality no-retire / forming excluded), or keep-and-document.
