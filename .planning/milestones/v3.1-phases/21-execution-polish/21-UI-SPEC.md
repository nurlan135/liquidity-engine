Existing terminal precedent (`report.tsx`, locked Phase 17 → Phase 20 contract). Locked to exactly 4 sizes and 2 weights. This phase adds NO new sizes or weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 12px (`text-xs`) | 400 (regular) | 1.5 |
| Label | 11px (`text-[11px]`, uppercase, `tracking-[0.1em]`) | 600 (semibold) | 1.2 |
| Heading | 16px (`text-base`) | 600 (semibold) | 1.2 |
| Display | 20px (`text-xl`) | 600 (semibold) | 1.2 |

Rules:
- Fire-rate strip line (`§5`, `data-slot="fire-rate-strip"`): Body role, 12px regular, `text-muted-foreground` — a quiet operator annotation, never headline prose.
- Fire-rate numeric count (`{n}` in `{n} fires / 7d`): Body role, 12px regular, `font-mono tabular-nums`.
- Threshold control label (`h4`, fixed Azerbaijani `Atəş Həddi`): Label role, 11px semibold uppercase `tracking-[0.1em]` — mirrors `Ağrı Həddi` / `s3-*` h4 idiom.
- Threshold value readout: Heading role, 16px semibold, `font-mono tabular-nums`.
- Reset affordance (`Sıfırla`): ghost button, Body role 12px.
- Only two weights exist: 400 and 600. No medium (500), no bold (700).

Accent reserved for (Phase 20 list carried verbatim, plus ONE explicit addition):
- live status dot (`data-slot="live-dot"`), `yüksək inam` conviction tier text, chart 'T' trigger pin marker, chart ticket entry/SL/TP price lines (EXECUTE only),

Pool lines NEVER use accent — BSL uses `--terminal-up` (#00ff88), SSL uses `--terminal-down` (#ff00ff) (Phase 20 D-09, unchanged).

Rationale: `--terminal-up`/`--terminal-down` are direction semantics (BSL/SSL); reusing them for calibration-band status would collide with pool-direction meaning on the same screen.

State treatments (locked precedents, do not restyle):
- Strip loading: `firingLog` unresolved renders nothing (no skeleton — the strip is an annotation inside an already-skeletoned §5 Card, not a standalone section).
- D-16 color-sync pin (test-only, no production change): `pool-overlay.ts` literals (`#00FF88`/`#FF00FF`/`#71717A`) pinned equal to `globals.css` `.dark` tokens with case-normalized comparison.

## Interaction Model (decided — open question closed)

21-RESEARCH.md Open Question §1 asked whether the threshold slider re-wires live trigger gates or is calibration-display only. **This contract decides: calibration-display only.**

- The slider value lives in a Zustand store slice (mirroring `ticketInputs.riskPct` + `setRiskPct` clamping precedent), persisted to localStorage (lazy `useState` initializer + write-through in setter, validated-on-read: finite number within [min, max], else code default; SSR-safe, never during render, never in `ict/`).
- The §5 fire-rate strip computes band status **against the operator's slider value** (annotation: "your threshold vs 7d evidence").
- `evaluateTrigger` / `checkFatalFlaw` / `computeTicket` keep reading the **code constant** — the store value is NEVER threaded into `src/lib/ict` (D-11/D-12/D-13: pools-never-vote, CALIBRATION-PROVISIONAL freeze, purity guard).
- Rationale: live-wiring would change calibration semantics and break replay determinism without a calibration band or population test — the same reason pool-gating is out of scope. The planner inherits this model and MUST NOT thread the threshold into pure functions; if a future phase wants live-wiring, it needs its own calibration-band requirement first.
- Slider spec: min 1, max 7 (fires/week), step 1, default = code constant (known base preserved in code, D-08); clamp-on-write; reset restores default.
