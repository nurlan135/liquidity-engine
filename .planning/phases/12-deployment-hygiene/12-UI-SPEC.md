### Dashboard Click-Path Copy — Token Deletion (DEPL-01, D-05, D-07)

Agent gives the user exactly this:

1. Open `vercel.com` → account avatar → Account Settings → Tokens.
2. Find the drill-automation token created for the v1.0 preview drill.
3. Delete (revoke) it and confirm the dashboard dialog.
4. Reply with exactly: `token deleted <YYYY-MM-DD>`.
5. If the token is already gone, reply with exactly: `token already gone <YYYY-MM-DD>`.
6. If the token turns out to still be live, it is deleted during the phase — keeping it as "intentional" is rejected (D-07).

The agent trusts the confirmation and documents it with the date. No API readback exists.

### Dashboard Click-Path Copy — Protection Switch (DEPL-02, D-01, D-02, D-04)

Agent gives the user exactly this:

1. Open the Vercel dashboard → project `liquidity-engine-nine` → Settings → Deployment Protection.
2. Set the scope to `Standard Protection` — NOT `All Deployments` (production must stay public; on Hobby, protecting prod is not available, so Standard is the correct scope).
3. Set the preview method to `Vercel Authentication` (Require Vercel login) — NOT a bypass secret and NOT open URLs (D-02).
4. If the dashboard already shows Standard Protection + Vercel Authentication, change nothing — verification-only path (D-04). No "document now, apply later" drift.

### Readback Request Copy (D-03 — trusted word alone is not enough)

Agent asks the user exactly this after any switch flip (or to confirm the already-matching state):

> Paste back the exact Deployment Protection scope and method strings as shown in Settings
> (or attach a screenshot). I will transcribe them into docs. Example of what I expect to
> record: `Standard Protection` + `Vercel Authentication`.

Agent transcribes the returned value into the PROJECT.md row. Screenshot or pasted value
required; verbal "it's done" is insufficient.

### Shell-History Check Copy (D-06, Pitfall 5)

Agent gives the user exactly this paste-ready check (history files are per-machine, outside
agent reach — absence of a history file is "no observation", never "clean"):

- Git Bash / bash: `grep -i vercel ~/.bash_history || echo NO-HISTORY-HITS`
- PowerShell: `Select-String -Pattern 'vercel' (Get-PSReadlineOption).HistorySavePath`

Record which command ran and its output, or record explicit user confirmation that no token
was ever exported in shell. Either way the evidence string goes in the task summary.

## Dashboard Readback Contract (DEPL-02 proof)

What exact setting strings the agent must capture and transcribe (source: 12-RESEARCH.md,
confirmed against current Vercel docs 2026-09-09):

| Setting | Required value | Reject |
|---------|---------------|--------|
| Protection scope | `Standard Protection` | `All Deployments`, `Legacy`, disabled |
| Preview method | `Vercel Authentication` | Bypass secret (`VERCEL_AUTOMATION_BYPASS_SECRET`), open URLs |
| Production reachability | `200` unauthenticated on prod page + `/api/yahoo` (agent curl probe) | Any auth challenge on prod |

Agent-side behavioral fingerprints (prescriptive, from 12-RESEARCH.md Code Examples):

- Public prod: `curl` prod page must return 200 with no auth (this is what `scripts/verify-deploy.sh` proves).
- Login-required preview fingerprint: `302` redirect to `vercel.com/sso-api` — valid ONLY against an existing preview URL.
- `404` on a preview URL means "no preview deployment to probe" — record as such; do NOT fail the gate and do NOT create a branch/preview just to probe it (Pitfall 3).

## PROJECT.md Row Contract (D-11, D-12)

Placement: append ONE row to the `## Key Decisions` table in `.planning/PROJECT.md`.
No new section, no new DEPLOYMENT.md, no SUMMARY-only record, no prose retelling of the
drill history. Compact means exactly this one row:

```markdown
| [12] Deploy hygiene: public prod + Vercel-login previews (Standard Protection); drill token deleted <YYYY-MM-DD>; drill-preview branch gone | Intentional post-drill state, dashboard-verified | ✓ Done — DEPL-01/02/03 |
```

Rules:

- The `<YYYY-MM-DD>` slot is filled with the user-confirmed token-deletion date (D-05).
- The protection clause uses the transcribed readback strings (D-03), defaulting to the
  exact wording above when readback matches Standard Protection + Vercel Authentication.
- One row only. Any additional paragraph about the drill history is a contract violation.
