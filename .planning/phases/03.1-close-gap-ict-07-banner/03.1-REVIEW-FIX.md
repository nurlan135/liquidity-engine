### WR-01: Banner subscribes to the selector function identity, not its derived value

**File:** `components/dashboard/terminal-shell.tsx:34-36`
**Commit:** 1e9dece
**What changed:** Replaced the three function-identity subscriptions
(`const selectRollover = useDashboard((s) => s.selectRollover)` +
`const rollover = selectRollover()`, same for `selectRange`/`selectDOL`)
with derived-value subscriptions
(`const rollover = useDashboard(useShallow((s) => s.selectRollover()))`,
same for range/dol) plus a `useShallow` import. Deviation from the
REVIEW.md snippet is deliberate and verified: the literal suggestion
`useDashboard((s) => s.selectRollover())` returns a fresh object per call,
so zustand's `Object.is` snapshot check never stabilizes and React throws
"Maximum update depth exceeded" (7/9 terminal-shell tests failed with the
naive form). `useShallow` (the StatusStrip precedent at
`components/dashboard/status-strip.tsx:12-14`) gives shallow-equal
snapshots, so the component re-renders on any input change
(`candles`/`contractHint`/`asOfBaku`) without the loop.
**Verification:** `node <main>/node_modules/vitest/vitest.mjs run src/terminal-shell.test.ts src/lib/store.test.ts` in the isolated worktree → 2 files, 20 tests, all passed. `eslint components/dashboard/terminal-shell.tsx` → clean.
**Tests run in:** isolated worktree (`.claude/worktrees/rf-03.1-552-1788691470`), reusing the main checkout's `node_modules` (worktree has no own install). Not re-run in the main checkout after teardown; re-run the same command there to reproduce.
