## Summary

Reviewed the ICT-07 banner scope at standard depth: the `selectRollover` Zustand
selector in `src/lib/store.ts` (ATR guard, full-candles delegation to
`detectRollover`) and the conditional `data-slot="rollover-banner"` block in
`components/dashboard/terminal-shell.tsx`, plus both test files. Cross-checked
the called pure functions (`src/lib/ict/rollover.ts`, `src/lib/ict/regime.ts`,
`src/lib/ict/types.ts`) for contract mismatches.

Core logic is sound: the ATR guard correctly degrades thin history to `null`
(`computeRegime` returns `atr: 0` below `MIN_CANDLES_FULL`, and `atr <= 0`
returns `null` before `detectRollover`, avoiding the `tripwire = 0`
false-positive path); full candles are delegated without a `closedOnly`
pre-filter (filtering happens once, inside `detectRollover`); the banner is
keyed directly on selector output, interpolates only `contractHint` /
`proximityWarning` as React text nodes (escaped, no `dangerouslySetInnerHTML`
or raw upstream body), reads no prices, and co-renders above — not instead
of — the chart and report. No secrets, injection sinks, or `eval`/`innerHTML`
usage found.

No BLOCKERs. Three warnings (one reactivity staleness issue, one guard gap,
one test-reliability coupling) and two info items below. All findings carry a
concrete fix.

## Warnings

### WR-01: Banner subscribes to the selector function identity, not its derived value

**File:** `components/dashboard/terminal-shell.tsx:36,40`
**Issue:** `const selectRollover = useDashboard((s) => s.selectRollover)` followed
by `const rollover = selectRollover()` subscribes to the stability of the
function reference (created once in the store, so it never changes) rather than
to the inputs the derived value depends on (`candles`, `contractHint`,
`asOfBaku`). The component re-renders today only because it separately
subscribes to `candles` / `lastUpdatedISO`, and `refresh` writes those together
with `asOfBaku` — but any `asOfBaku`- or `contractHint`-only update does not
re-render the banner. The test file itself documents the workaround
(`src/terminal-shell.test.ts:347-349`: "setting it post-render alone would not
re-render the function-subscription", hence fake-timer clock pinning). The same
pattern affects `selectRange` / `selectDOL` (lines 34-35, 38-39), so the whole
center panel shares the staleness. A future caller that bumps `asOfBaku`
midnight-rollover without new candles would leave a stale or missing
proximity warning on screen.
**Fix:**
```tsx
// Subscribe to the derived value so any input change re-renders:
const rollover = useDashboard((s) => s.selectRollover());
const range = useDashboard((s) => s.selectRange());
const dol = useDashboard((s) => s.selectDOL());
```

### WR-02: Envelope guard accepts an empty-string `contractHint`, banner then renders an identifier-less title

**File:** `src/lib/store.ts:50`
**Issue:** `isValidEnvelope` checks only `typeof env.contractHint !== 'string'`,
so `contractHint: ''` passes validation and is stored. The banner then renders
`ROLLOVER SUSPECT ·  — range may span a contract roll; …` with a blank
identifier, defeating the banner's purpose (naming the suspect contract). The
`hint-passthrough` test pins the non-empty path but no test pins the empty
path. (`source` has the same `typeof`-only check, but it is not banner-facing.)
**Fix:**
```ts
if (typeof env.contractHint !== 'string' || env.contractHint.trim().length === 0) return false;
```

### WR-03: Boundary test crafts the "exactly 3xATR" gap from a different ATR than the selector uses

**File:** `src/lib/store.test.ts:212-239`
**Issue:** The `boundary-clear` test computes `atr` from `candles.slice(0, -1)`
(line 218) and sets the final gap to exactly `3 * atr`, but `selectRollover`
recomputes ATR over the full 35 candles *including* the modified last bar
(`src/lib/store.ts:190`). The test passes today only because Wilder smoothing
inflates the full-input ATR when the last true-range grows, so the gap lands
strictly below the real tripwire — i.e. the assertion depends on ATR
monotonicity internals rather than on the `>` vs `>=` boundary it claims to
pin. A change to smoothing that preserves the public contract could flip this
test without any behavior regression (or, worse, mask a real off-by-one).
**Fix:** Compute the reference ATR the same way the selector does — craft the
gap iteratively (solve `gap == 3 * computeRegime(fullCandles).atr` by fixed-point
iteration), or assert against `detectRollover` directly with an explicit `atr`
argument for the exact-boundary pin and keep the store test as a
"stays clear near the tripwire" integration check:
```ts
// Exact-boundary pin belongs at the pure-function level:
import { detectRollover } from '@/src/lib/ict/rollover';
const flag = detectRollover(candles.slice(0, -1), atr, '2026-01-25', 'NQ=F · CME');
// …then craft the last-bar gap against the full-input ATR for the store pass.
```

## Info

### IN-01: Ineffective `vi.resetModules()` in terminal-shell test setup

**File:** `src/terminal-shell.test.ts:168-169`
**Issue:** `beforeEach` calls `vi.resetModules()`, but the modules under test
(`TerminalShell`, `useDashboard`) are imported once via top-level `await import`
(lines 77-78), so the reset clears a registry nobody re-reads; isolation relies
entirely on the manual `useDashboard.setState(...)` reset below it. The call is
dead and implies an isolation guarantee it does not provide.
**Fix:** Remove the `vi.resetModules()` line (the manual `setState` reset is the
real isolation mechanism), or re-import per test like `store.test.ts` does.

### IN-02: Duplicated candle fixtures across the two test files

**File:** `src/terminal-shell.test.ts:84-124` (duplicates `src/lib/store.test.ts:5-27,170-191`)
**Issue:** `fixtureCandles` and `gappedCandles` are defined independently in both
test files with the same shapes and magic constants (10pt step, +15/-12 wicks,
+250 gap, 35-bar history). A future change to the regime floor
(`MIN_CANDLES_FULL`) or tripwire multiple must be edited in four places; drift
between the copies would make the two suites disagree silently.
**Fix:** Extract one shared factory (e.g. `src/test-utils/ict-fixtures.ts`) and
import it from both suites. Test-only change; no implementation risk.
